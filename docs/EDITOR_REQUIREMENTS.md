# 향후 게시판 HTML 편집기 요구사항

이번 UI 배포에는 게시판과 편집기를 추가하지 않는다.

현재 FAQ는 `index.html`의 `faqList`가 공식 원문이며 `node scripts/build-faq.cjs`가 독립 `faq.html`을 만든다. 별도의 FAQ 관리자 편집 API/DB는 없다. 원문 11개 및 4/4/3 구성은 유지한다. FAQ HTML 수정·삭제 검증은 격리된 임시 복제에서 수행하며 운영 문답을 변경하지 않는다.

향후 게시판은 다음을 저장 계층부터 실제 게시 화면까지 검증해야 한다.

- HTML 형식 작성·수정, HTML 소스 보기 및 편집.
- 본문 전체 삭제, 선택 문단과 이미지 삭제, 기존 콘텐츠 전체 교체.
- 삭제와 빈 본문을 명시적 수정으로 처리한다. 빈 값에 이전 내용을 fallback하거나 `value || oldValue`로 복원하지 않는다.
- DB·API·편집기·게시 화면에 같은 저장 버전과 HTML이 반영돼야 한다. 서버 승인 후 캐시/상태를 갱신하고 이전 응답이 새 수정을 덮지 않도록 한다.
- 저장·새로고침·재진입·브라우저 뒤로가기 후 삭제한 콘텐츠가 다시 나타나지 않아야 한다.
- HTML 편집 권한과 서버 저장 검증을 적용하고 게시 시 안전한 HTML만 허용한다. 미리보기와 게시 화면은 같은 정제 규칙을 사용한다.
- 부분 삭제, 전체 삭제, 이미지 삭제, 전체 교체, 동시 수정 충돌, 저장 실패/재시도를 통합 테스트한다. DB 저장 HTML과 API 조회 HTML 및 실제 게시 화면을 각각 비교한다.

설치 상태 보강의 API 근거: [Chrome Get Installed Related Apps](https://developer.chrome.com/docs/capabilities/get-installed-related-apps). 지원하는 브라우저에서 확인 가능한 현재 서비스의 설치 결과만 사용한다. iOS 일반 브라우저에서는 설치 여부를 추측하지 않으며 standalone 신호와 저장된 설치/다시 보지 않기 상태를 사용한다.
